🗂️ Vocabulary word/meaning editor — 4 layout alternatives

Static design mockup, not wired to the real app. Each layout shows a Desktop preview and a Mobile preview side by side.

1 · Flashcard 2 · Labeled form grid 3 · Accordion list 4 · Minimal / floating toolbar

1 · Flashcard front / back split

Each word is its own card with a visible "front" (the term) and a shaded "back" (the meaning) — like an actual flashcard, which is literally what these are being trained as. The formatting toolbar is hidden behind a small "Aa" toggle instead of always sitting on screen.

  • Term vs. meaning is obvious at a glance (two visually distinct zones, not two grid columns of equal weight).
  • The always-visible highlight/color/size toolbar — the main clutter in the current design — is now opt-in.
  • Delete moves to a quiet corner "×" instead of its own dedicated 34px column.

2 · Labeled form grid explicit field labels

The current table has column headers only once, at the very top — scroll past a few rows and it's unclear which side is which. This puts a small "WORD / TERM" / "MEANING" label directly on every single field, always in view, and arranges word-pairs two-per-row on desktop for density.

  • Every field is self-labeled — no need to scroll back up to remember which column is which.
  • Toolbar becomes one compact icon row directly under the label, not a second sub-grid.
  • Delete sits as a quiet icon in the card's corner rather than a full grid column.

3 · Accordion list scan first, edit on demand

For a topic with a lot of words, the current design shows every field, toolbar, and link-chip for every word all at once — a wall of controls. This collapses each word to one scannable line (term + a preview of the meaning) and only expands the full editor for the row you're actually working on.

  • Scanning 20 words is just 20 short lines, not 20 stacked toolbars.
  • Editing controls only exist on screen for the one row you opened — nothing to parse elsewhere.
  • Naturally mobile-friendly already, since a collapsed row is just text on one line.

4 · Minimal, floating toolbar Notion/Medium-style

No permanent buttons at all in the common case. Term reads like a document heading, meaning reads like plain body text underneath it — formatting only ever appears when you actually select text, right next to your selection. Try selecting some meaning text below on desktop.

  • Zero toolbar clutter until you're actually formatting something.
  • Reads like plain text you're annotating, not a spreadsheet you're filling in.
  • Row actions (delete/link/attach) fade in on hover instead of permanently occupying space.
